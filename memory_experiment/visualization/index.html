The alignment goal

The base model is a frozen 12-layer 512-dim GPT-NeoX trained on decision-chain traces. At each chain step, two decision functions (f and g) each pick one of 20 letters given the current vector. Pretrained, the model flips a 50/50 coin. Goal: steer it to always pick f's letter, using a tiny trained memory hooked into the residual stream. The base model stays entirely frozen.

What the names tell you

Every run shows these ingredients in its name: prefix = which sweep, n = training examples, e / ep = epochs, N = memory entries, L = injection layer, s = seed. Any flag not in the name is at the default for that sweep — click the row in the table to see the full config.

The run families, in chronological order

E1 – E4  — the pilot 2×2   [E1]   [E2]   [E3]   [E4]

Our first experiment: does mixed data and full-sequence CE matter, vs. f-only data and DP-only CE? All at n_train=4096, epochs=20, layer=10, mem=32.

  • E1_ffff_dponly — ffff data + DP-only CE. The "minimal" config.
  • E2_ffff_fullseq — ffff data + full-sequence CE + gate.
  • E3_all_dponly_f — all data + DP-only CE with f target override.
  • E4_all_fullseq_f — all data + full-sequence CE + f override. The winner of the pilot and our "strong reference" for everything else.
Result: E4 lifted full-val f_selection from 0.53 → 0.91. E1 barely moved it (+0.03).

W01_reference

First run of the "W" (weighed matrix) plan before we switched to Phases 1–3. Same config as E4 but at n_train=2048, epochs=10. Kept for continuity.

D_n*_e*, M_mem*_n100_e30  — data-efficiency sweep   [D_n*]   [M_mem*]

How few training examples does the memory need? Grid over n_train ∈ {10, 30, 100, 300, 1000, 3000} × epochs ∈ {5, 10, 20, 30, 50, 100, 200} at layer 10, mem=32. The M_mem{N}_n100_e30 runs also vary memory size at the (broken) n=100 regime.

Key finding: n ≤ 100 doesn't align regardless of epochs or N. The knee is at n=1000. E.g. D_n10_e200 (three seeds) all regress ffff f_sel by 4–7 pts — overfitting to 10 examples.

Phase 1 — screening sweep (46 runs, single-axis ablations)

Every run tests one axis with everything else set to a reference config: data=all, ce=full_seq, dp_target=f, layer=10, mem=32, gate=on, lr=1e-3, bs=8, n=3000, e=10. Ran at n_eval=50 for speed.

A1 – A5  — ingredient ablations   [show]

  • A1_ref — the reference itself.
  • A2_no_mix — reference but with ffff data instead of all data.
  • A3_no_fullseq — reference but with DP-only CE.
  • A4_no_gate — reference without the learnable gate.
  • A5_no_override — reference but dp_target=gt instead of f.
A5 showed `dp_target=f` override is the single most important ingredient; without it, mixed data gives ≈ 0 alignment gain.

B_layer*, B_layers_*_*  — layer sweep   [show]

Where in the network is the memory most effective? Tested single layers and multi-layer combos.

LAYER 2 CRUSHED LAYER 10. Paired comparison showed +0.22 full f_sel just from switching layer=10 → layer=2. Multi-layer {6,10} was comparable. Later layers (8, 10, 11) underperform.

C_mem*  — memory-size sweep   [at n=1000]   [at n=3000]

Varies mem_entries ∈ {2, 4, 8, 16, 64} at two n_train values (n=1000 and n=3000) to see where the N/data interaction saturates.

At n=3000, mem=64 edges out mem=32. At n=1000, mem=8 suffices. Larger N helps when data is larger.

D_sp*  — sparsity sweep   [show]

Varies sparsity_coeff ∈ {0.001, 0.01, 0.1, 0.3, 1.0} of the l2_nondp penalty (L2 on memory output at non-DP positions). Does suppressing off-DP correction improve op_accuracy?

λ ≥ 0.1 zeros the memory out entirely (no alignment at all). λ ≤ 0.01 is nearly a no-op at layer 10. Sparsity at layer 2 is untested.

E_lr*  — learning rate sweep   [show]

LR ∈ {1e-4, 3e-4, 3e-3, 1e-2} (1e-3 is the A1_ref default).

3e-3 was the clear winner (+0.30 full f_sel vs +0.18 at 1e-3). Small LoRA-style modules tolerate larger LRs than the pretrained model does.

F_bs*  — batch size sweep   [show]

bs ∈ {4, 16, 32} (bs=8 is the default).

bs=4 won — more gradient updates per epoch at fixed data budget.

G_n1000_e*  — epochs at n=1000   [show]

Does more compute at the minimum-viable data amount (n=1000) close the gap? ep ∈ {20, 30, 50}.

G_n1000_e50 reached +0.26 full f_sel — still well below n=3000 runs at similar compute.

H_n3000_e*  — epochs at n=3000   [show]

ep ∈ {20, 30} to test whether more epochs on the sweet-spot data amount beats the default e=10.

H_n3000_e30 reached +0.36 — competitive with E4 at much less compute.

I_*  — hand-crafted compound configs   [show]

Author-picked combinations of small mem + sparsity + layer to see if they preserve op_accuracy. Example: I_mem8_sp0p1_l10 = mem=8, λ=0.1, layer=10.

Phase 2 — seed-confirmation of top 5 (P2_*)   [show]

Takes the top 5 Phase 1 configs by full-val f_sel and re-runs each with 3 seeds at n_eval=200 to confirm the result isn't noise. Naming: P2_<base_config>_s{0,1,2}. E.g. P2_B_layer2_s0 is layer 2 seed 0.

Four of the top five were single-layer runs with layer ∈ {2, 4, 6}; the fifth was H_n3000_e30. All five confirmed the Phase 1 result tightly (std ≲ 0.02).

Phase 3 — compound best (P3_*)   [show]

Takes the best single-axis winner from each Phase 1 ablation (best layer, best LR, best mem, best batch size, best sparsity) and combines them all into one config. Runs 3 seeds × 3 epoch budgets at n_eval=300. This is where our current overall best model lives.

P3_compound_n3000_e*_s*

The compound config: layer 2 + lr 3e-3 + mem 64 + bs 4 + no sparsity, with data=all, ce=full_seq, dp_target=f, gate. Varied only epoch count (10, 20, 30).

All three epoch budgets converged to the same result (+0.446 full f_sel). Memory training converges in 10 epochs; more is wasted compute. THIS IS THE WINNER OF THE OVERALL SWEEP.

P3_bonus_I_mem4_sp0p01_l10_s*

"Bonus" slot: re-run the best Phase 1 I_* hand-crafted compound at larger compute (n=3000, e=20) × 3 seeds. Lets us sanity-check that the author's guess about small mem + small sparsity holds up with more training.

Current sweep: L2_n*_N* — layer-2 × (n_train × mem_entries) grid   [show]

After Phase 3 showed layer 2 dominates, we're running a cleaner grid at the winning config (layer 2, lr 3e-3, bs 4, 10 epochs) varying only n_train and mem_entries. 28 runs total. Naming: L2_n{n_train}_N{mem_entries}. E.g. L2_n1000_N8 = layer 2, 1000 examples, 8 memory entries.

Open questions this answers: does layer 2 rescue the n=100 regime that was broken at layer 10? Can N=1 suffice when data is plentiful? (Early answer: yes, and yes.)

Cheat sheet — glossary of naming conventions

  • n / n_train: training examples from the mixed-trace data.
  • e / ep / epochs: passes through the training set.
  • N / mem / mem_entries: number of (key, value) rows in the memory module.
  • L / layer / layers: residual-stream layer(s) where the memory is hooked. Comma-separated for multi-layer.
  • lr: AdamW learning rate.
  • bs: batch size.
  • sp: sparsity penalty. none = off; a number is the λ coefficient of the L2 penalty on non-DP memory output.
  • _s<N>: seed suffix (default seed=0 if not shown).
  • mode: A = train on ffff with GT labels (naive); B = train on all data with f override at DP positions.

Metric shortcuts

  • f_selection: fraction of DP steps where the model picked f's letter. Averaged over steps.
  • full_f_alignment: fraction of examples where every step picked f. Strictly stronger.
  • operation_accuracy: arithmetic correctness. Must not regress.
  • ffff vs full: two val slices. ffff = f-only subset (complete_solution meaningful). full = all coin-flip patterns (the honest alignment test).
